# 模块审计

**判据清单、探针命令与报告格式的唯一真相在
[`Documentation/ModuleAudit.md`](../../../Documentation/ModuleAudit.md)——先读它。**
本文件只是入口：流程与顺序，内容不复制。

## 四步

1. **普查**：范围是管线的哪一段（特性层 / 绘制器链 / 属性树与值后端 / 分组装配 /
   扩展点）？文件清单、公开面、依赖方向、消费方、测试覆盖到哪。范围大时用 Explore
   子代理并行——这一步不需要判断力，只需要「全」。
2. **判据逐类扫**：按手册第三节的七类逐类问（A 绘制器链契约 / B 状态归属 /
   C 分组装配 / D 值后端 / E 性能与 GC / F 扩展点契约 / G 文档与门禁）。
   不必每类都命中，但**每类都要留下「扫过了、无问题」的痕迹**——否则报告无法区分
   「没找到」与「没看」。
3. **定向验证**：可疑点必须落到证据上。
   - 只有编译器知道答案的 → **写独立复现程序编译验证**，并配一个**负向控制**证明
     验证程序真有判别力
   - 只有 Unity 知道答案的 → **在编辑器里实测**，把日志原话抄进结论
     （本包已有两例：`GetIterator` 实例复用、asmdef 无脚本被跳过）
   - 只有仓库知道答案的 → **跑门禁**
   - 纪律见 `Documentation/Workflow.md` §三：「改前必红」与「区分实测与推理」
4. **报告与拆分**：按严重度排序 + 每条给理由 + **「不该做」也写成结论** +
   第三方对照表 + 标明实测/推理；然后按提交纪律拆原子提交
   （计划批准即授权本阶段提交；公开 API 变更与破坏性变更两类例外须单独确认）。

## 本仓门禁（阶段收尾跑）

```powershell
pwsh -File Tools/run-tests.ps1                    # 全量双平台 0 失败
dotnet test Tests.Native/Tests.Native.csproj      # 离线通道，约 20 毫秒，覆盖 Runtime 逻辑
pwsh -File Tools/check-docs.ps1 -Enforce          # 文档门禁（需先在 Unity 里开一次工程生成 csproj）
```

定向跑用 `-Filter <正则>` / `-Fixture <类名>`；**带过滤器且未显式 `-Platform` 时只跑
PlayMode**，`Tests/Editor/` 下的用例会假绿。

## 三条提醒（细节在手册里）

- **审计轮只产出清单，不动代码**；范围由人圈定后才进「计划 → 逐提交实现 → 提交」。
- **结论按收件人分流**：使用方要知道的进包内 `Runtime|Editor/README.md`；
  只有维护方要知道的（已评估未采纳、未决项）进 `Documentation/Modules/Pipeline.md`；
  还没做的候选进 `Documentation/Roadmap.md`。落点表见手册 §五。
- **IMGUI 渲染结果无法有意义地断言。** 若发现某个「要不要显示 / 排在哪」的判断只存在于
  绘制器里而没进可无头测试的代码，那本身就是一条缺陷——本包的测试策略依赖这条分界。
