# Overview 示例

展示 XInspector 的最小可用形态。

## 怎么用

1. 场景里新建一个空物体（或直接用任意现有物体）；
2. 把 `OverviewComponent` 挂上去；
3. 选中它，看 Inspector。

预期看到：

```
玩家档案                              ← 类级 [Title]
身份                                  ← 成员级 [Title]
┌ 基础 ─────────────────────────┐
│ Player Name   [ Player      ] │
│ ┌ 属性 ─────────────────────┐ │
│ │ Health        [ 100       ] │ │
│ │ Speed         [ 5         ] │ │
│ └───────────────────────────┘ │
└───────────────────────────────┘
Ungrouped        [ 1 ]                ← 夹在两个分组之间，留在原位
┌ 附加 ─────────────────────────┐
│ Note          [ 末尾的分组  ] │
└───────────────────────────────┘
```

## 这个示例在演示什么

- **类级与成员级标题走同一条路径。** 两者都是普通的特性+绘制器配对，
  没有「类级特例」这回事。
- **路径即嵌套。** 只写了 `[BoxGroup("基础/属性")]`，外层的「基础」分组由构建期合成，
  不必再写一遍。
- **未分组字段留在原位。** 分组节点落在其首个成员出现的位置，
  所以 `Ungrouped` 夹在「基础」与「附加」中间，而不会被挤到末尾——
  后者是「先摆所有分组、再摆散字段」那种朴素实现的必然结果。
- **接入只要三行。** `Editor/OverviewComponentEditor.cs` 就是全部——
  XInspector 不自动接管任何类型。

## 关于自动接管

如果你不想为每个类型手写编辑器，可以在
Project Settings → Player → Other Settings → Scripting Define Symbols 里加上
`XINSPECTOR_AUTO_EDITOR`。那会启用一个独立的门控程序集，让带特性的类型自动接管；
删掉该宏即完全恢复 Unity 默认行为。没用到 XInspector 的类型外观不会改变——
自动编辑器会退回 `DrawDefaultInspector()`。
